# Human Microbiome Compendium
# Dataset Documentation v1.1.0

The Human Microbiome Compendium is a collection of publicly available human microbiome samples, processed using a uniform pipeline. The dataset currently contains 16S rRNA gene amplicon sequencing data from human gut microbiome samples. This file describes the data in the compendium and where it came from. Data was processed as described [in our preprint](https://www.biorxiv.org/content/10.1101/2023.10.11.560955v1).

**Important changes in this release:**

* The one procedural change made after version 1.0.1 was in process for classifying amplicon sequence variants (ASVs). Previously, taxonomic assignments for each ASV were inferred for each project independently. For this release, all ASVs in the compendium were consolidated and classified together, so a sequence observed in multiple studies will always have the same taxonomic assignment.

## Files

* **`taxonomic_table.csv.gz`** – The taxonomic table describing the composition of each sample by listing the read counts for each observed taxon.
* **`sample_metadata.tsv`** – Contains sample-level metadata for things such as total bases and world region.
* **`projects.csv`** – Contains project-level metadata for properties such as inferred amplicon choice, publication links and mechanical lysis.
* **`tags.tsv.gz`** – Contains the key–value pairs used to define properties associated with individual samples. Retrieved from BioSample.
* **`project_asv_tables.zip`** – An archive of ASV tables in which each file lists the ASVs observed in a single project, along with the read counts of each ASV observed in each sample.
* **`obs_md.txt.zip`** – This lists the sequences associated with the ASVs described in the project ASV tables. ASV numbers (and their sequences) are shared across all projects.
* **`silva_nr99_v138.2_train_set.fa.gz`** – A copy of the SILVA 138.2 Ref NR 99 reference database, formatted to work with DADA2. At the time of release, a canonical version of this resource had not yet been made, so we generated one for use here. It was created with [the code](https://github.com/mikemc/dada2-reference-databases/) used to create previous versions of the DADA2 references.
* **`missing_levels.csv`** – A file generated by the same "dada2-reference-databases" code used to format the reference database (called "bad-taxa" in that repository). This examines the final formatting of the taxa in the list to find those that describe fewer ranks than expected.
* **`gg2-2022.10-cref99.biom.qza`** – A new taxonomic table (compressed as a QIIME Zipped Artifact) with classifications made using Greengenes2.
* **`gg2-2022.10-cref99.reps.fna.qza`** – A FASTA file listing representative sequences for each facet of the Greengenes2 taxonomic table. (For this classification, ASVs were clustered at 99% similarity before assignment.)
* **`gg2-2022.10-cref99.tax.tsv.qza`** – A tab-separated file listing the taxonomic assignments made for each facet of the Greengenes2 table.

## Formats

### taxonomic_table.csv.gz
* The taxonomic table describing the composition of each sample by listing the read counts for each observed taxon. The file has one header row.
* The first column (without a title in the header) holds the row numbers.
* The second column, `sample`, lists the BioProject accession and SRA run accession separated by an underscore.
* The remaining columns each describe the sample-level read counts for a single taxon. The header of each of these columns lists the taxon with all available taxonomic ranks down to the genus level, separated by periods. Any levels for which a classification is not available are indicated with `NA`.


### sample_metadata.tsv
* **`srs`** – The SRA sample accession associated with this sample
* **`project`** – BioProject
* **`srr`** – SRA run accession associated with this sample. (Currently, there is a 1-to-1 mapping between srs and srr IDs.)
* **`library_strategy`** – Indicates the type of sequencing performed (RNA-seq, WGS, etc). Samples in this release were filtered using this field, so the only value is "AMPLICON". Retrieved from the "experiment package" associated with the sample.
* **`library_source`** – Indicates the type of data being generated (metagenomic, metatranscriptomic, synthetic, etc.). Samples in this release were filtered using this field, so the only values are "GENOMIC" and "METAGENOMIC". Retrieved from the "experiment package" associated with the sample.
* **`pubdate`** – Indicates the date the sample was "published" according to NCBI. Retrieved from the run associated with the sample.
* **`total_bases`** – Indicates the number of bases submitted as part of the sequencing run. Retrieved from the run associated with the sample.
* **`instrument`** – Sequencing instrument reported to NCBI. Retrieved from the "experiment package" associated with the sample.
* **`geo_loc_name`** – The value of the sample's "geo_loc_name" tag, according to BioSample data. (These tags also appear in the "tags.tsv" file.)
* **`iso`** – The ISO 3166-1 alpha-2 country code of the sample's country of origin, as inferred from the geo_loc_name tag. Each unique geo_loc_name value is manually annotated with a country, if possible. Ambiguous or missing values are listed here with the value "unknown".
* **`region`** – The world region encompassing the country listed in the "iso" field. Regions here are as defined by the United Nations in their [Sustainable Development Goals reporting](https://unstats.un.org/sdgs/indicators/regional-groups/).


### tags.tsv
Each row indicates one attribute associated with a single sample.

* **`project`** – The BioProject associated with the sample
* **`srs`** – SRA sample accession
* **`srr`** – SRA run accession associated with this sample
* **`tag`** – The attribute name. (This represents the "harmonized_name" property if available, otherwise "attribute_name".)
* **`value`** – The value of the attribute specified by the "tag" field. For example, an entry with a tag `weight` may have a value `123`.


### projects.csv
Project-level metadata. Each row indicates a single BioProject represented within the compendium.

* **`project`** – The BioProject accession.
* **`link`** – A link to the earliest known publication associated with the BioProject that appears to be from the same group that deposited the data. Whenever possible, the link uses the paper's Digital Object Identifier (DOI). This is manually curated.
* **`amplicon`** – The hypervariable region amplified for sequencing in this study. This is inferred by aligning the study's ASVs to the E. coli genome. Studies sequencing regions that bridge more than one hypervariable region are classified with a hyphen (e.g. `v3-v4`). In cases where an amplicon could not be identified, such as cases where one study used more than one set of primers, this is left blank.
* **`avg_length`** – The mean length of the ASVs identified in the study. ASVs are identified late in the quantification process, so this is after trimming, filtering and merging.
* **`bead_beating`** – A binary field indicating whether the project used a DNA extraction protocol that includes mechanical lysis. This is inferred using text-mining of the publication, when available. If a project's publication does not explicitly specify whether bead beating was used but lists an extraction kit (e.g. Qiagen PowerSoil) that includes bead beating, this is still set to `TRUE`.
* **`kit`** – Extraction kit used in the study, as annotated manually. This field is currently independent of the text-mining results used for the bead beating field.
* **`sample_type`** – Manual annotation of the source of the materials analyzed in the project, according to the publication. This is generally "stool" but in some cases contains values such as "mucosal tissue". In cases where more than one source is indicated (e.g. "stool and milk"), this refers to amplicon sequencing described in the publication, not necessarily in the samples included in the compendium. If samples from the project were deposited in more than one category (e.g. "human gut metagenome" and "human milk metagenome"), only the gut samples would be included here. However, some projects deposit all samples in the same category regardless of content, so some projects may combine samples from multiple body sites. Manually annotated.
* **`condition`** – The disease or condition being examined in the study, based on the content of the publication. Manually annotated.
* **`subjects`** – The population being studied, based on the content of the publication. Manually annotated.
* **`notes`** – Notes from annotators, usually on the interpretation of methods from the publication.


### project_asv_tables.tar.gz
* Unpacking this archive will create a directory called "asv" in which each tab-delimited file describes the processed samples from a single BioProject.
* Please note the formatting of these tables is transposed relative to the taxonomic table above: Each row is a single ASV, and each column is a sample, indicated by the SRA sample accession.


### obs_md.txt.gz
* **`#OTUID`** – the ID of a single ASV, as reported in the project ASV tables.
* **`sequence`** – The inferred sequence of the ASV


### Greengenes2 files
* Three files documenting the taxonomic classifications made using Greengenes2, which are made using OTUs instead of ASVs.
  * `gg2-2022.10-cref99.biom.qza` – The taxonomic table listing the number of reads per sample that were classified into a set of features (ASVs clustered at 99% identity).
  * `gg2-2022.10-cref99.reps.fna.qza` – The representative sequences for each feature.
  * `gg2-2022.10-cref99.tax.tsv.qza` – The taxonomic assignments made for each feature.
* Files are compressed as QIIME Zipped Artifacts to streamline their use with QIIME 2.
* Several relevant files are stored in the repository at https://doi.org/10.5281/zenodo.13733483
    * The steps used to generate these files are listed in the "phylogenetic.sh" file
    * The "gain_setup.sh" and "gain_iteration.sh" files offer examples of how to manipulate the data and export it to other formats.
